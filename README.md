# tgbot — напоминания из Google Calendar в Telegram

Telegram-бот, который периодически опрашивает Google Calendar и присылает
напоминания о предстоящих событиях в подписанные чаты (за N минут до начала,
настраивается).

## Как это работает

- Бот подключается к Google Calendar через **сервис-аккаунт** (без ручного
  OAuth-логина на сервере) и читает один календарь, указанный в конфиге.
- Каждые `POLL_INTERVAL_SECONDS` секунд бот запрашивает события на ближайшие
  `LOOKAHEAD_HOURS` часов и для каждого события проверяет пороги
  `REMINDER_MINUTES_BEFORE` (например, 60 и 10 минут до начала).
- Каждое напоминание отправляется один раз на чат — это отслеживается в
  локальной SQLite-базе (`DATABASE_PATH`), поэтому дубликатов не будет даже
  при частом опросе или перезапуске бота.
- Подписаться/отписаться от напоминаний может **любой человек**, написав
  боту `/subscribe` — все подписчики следят за одним и тем же календарём,
  который вы указали (см. «Как поделиться ботом» ниже).
- Календарь, пороги напоминаний, горизонт просмотра, интервал опроса и
  часовой пояс можно менять прямо в Telegram командами `/set_*` — без
  редактирования `.env` и без перезапуска бота (см. «Настройка через
  Telegram» ниже).
- И в списках событий (`/today`, `/upcoming`), и в напоминаниях бот
  показывает **и начало, и конец** события.
- Каждый день в `DAILY_DIGEST_TIME` (по умолчанию в 10:00) всем подписчикам
  приходит сводка со всеми событиями на сегодня.
- Администратор может полностью удалить событие из календаря прямо из
  Telegram — командой `/delete_event` с подтверждением кнопками.
- Бот узнаёт олимпиады среди вручную вписанных в календарь событий по
  названию (жёстко зашитый список сайтов, см. `bot/olympiads.py`) — такие
  события помечаются бейджем и получают отдельные напоминания о дедлайне
  регистрации/отборочного этапа (см. «Олимпиады» ниже).
- По кнопке в `/start` открывается **Mini App** — полноценное веб-приложение
  внутри Telegram с тем же функционалом в удобном виде (списки, кнопки,
  поля настроек вместо команд). Требует отдельной настройки (домен + HTTPS)
  — см. «Mini App» ниже; без неё всё остальное работает как обычно.

## 1. Создать Telegram-бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram, отправьте
   `/newbot` и следуйте инструкциям.
2. Скопируйте выданный токен — это `TELEGRAM_BOT_TOKEN`.

## 2. Настроить доступ к Google Calendar

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и
   создайте (или выберите) проект.
2. Включите **Google Calendar API**: APIs & Services → Library → Google
   Calendar API → Enable.
3. Создайте сервис-аккаунт: APIs & Services → Credentials → Create
   Credentials → Service account.
4. У созданного сервис-аккаунта откройте вкладку **Keys** → Add Key →
   Create new key → JSON. Скачается файл ключа — сохраните его в проекте как
   `service_account.json` (или укажите свой путь в
   `GOOGLE_SERVICE_ACCOUNT_FILE`). **Не коммитьте этот файл** — он уже
   добавлен в `.gitignore`.
5. Скопируйте email сервис-аккаунта (вида
   `xxxx@xxxx.iam.gserviceaccount.com`).
6. В Google Calendar откройте настройки нужного календаря → **Share with
   specific people** → добавьте email сервис-аккаунта с правом **«Make
   changes to events»** (именно это право, не «See all event details» —
   бот теперь не только читает события, но и умеет удалять их по команде
   `/delete_event`).

   **Если вы настраивали бота раньше** и выдавали сервис-аккаунту только
   чтение — зайдите в настройки календаря и повысьте его право доступа до
   «Make changes to events», иначе `/delete_event` будет падать с ошибкой
   доступа.
7. Возьмите **Calendar ID** в настройках календаря (раздел «Integrate
   calendar») — это либо `primary` для основного календаря аккаунта-владельца,
   либо адрес вида `xxxxx@group.calendar.google.com` для отдельного
   календаря.

## 3. Настроить и запустить бота

### Вариант А — с Windows, без захода на сервер руками (`deploy_from_pc.bat`)

Разворачивает и обновляет бота на сервере по SSH прямо с вашего компьютера —
не нужно самому заходить в консоль сервера и набирать команды.

Весь текст внутри `deploy_from_pc.bat` (комментарии и сообщения) специально
на английском — кириллица в `.bat`-файлах ломает разбор команд в `cmd.exe`
в зависимости от кодовой страницы, из-за чего даже `git`/`ssh` может
перестать находиться с ошибкой «is not recognized». Это не баг в вашей
системе, а особенность `cmd.exe` — поэтому сам скрипт выводит сообщения
по-английски, а описание ниже на русском.

**Подготовка (один раз):**
1. Скачайте этот репозиторий (ветка
   `claude/telegram-google-calendar-reminders-nna72g`) на свой компьютер в
   любую папку — `deploy_from_pc.bat` запускается оттуда.
2. В этой же папке создайте `.env` (скопируйте `.env.example` → `.env` и
   впишите `TELEGRAM_BOT_TOKEN`) и положите рядом `service_account.json`.
3. (Настоятельно рекомендуется, иначе пароль от сервера придётся вводить
   по несколько раз за запуск) Настройте вход по SSH-ключу — один раз в
   PowerShell:
   ```powershell
   ssh-keygen -t ed25519
   type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@ВАШ_IP "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
   ```
   (при генерации ключа можно просто нажимать Enter на все вопросы; пароль
   root спросят последний раз — на шаге копирования ключа)

**Запуск:**

Дважды кликните `deploy_from_pc.bat` (или запустите из PowerShell). При
первом запуске спросит IP сервера и запомнит его в `server.ini` (этот файл
не попадёт в GitHub — он в `.gitignore`, в нём ваш IP). Дальше скрипт сам:
клонирует/обновляет код на сервере, при первом запуске загружает `.env` и
`service_account.json` (если на сервере их ещё нет — существующие не
перезатирает, чтобы не затереть то, что вы правили прямо на сервере,
например `ADMIN_CHAT_IDS`), и запускает там `deploy.sh`.

Чтобы обновить бота после того, как я внёс изменения в код — просто
запустите `deploy_from_pc.bat` ещё раз.

### Вариант Б — одним скриптом прямо на сервере (`deploy.sh`)

Если вы уже зашли на сервер по SSH сами (или вариант А недоступен —
например, нет SSH-клиента):

```bash
git clone -b claude/telegram-google-calendar-reminders-nna72g https://github.com/matuskin155-prog/tgbot.git
cd tgbot
sudo bash deploy.sh
```

Скрипт сам поставит Python/venv, зависимости и настроит автозапуск
через systemd. При первом запуске он создаст `.env` и остановится — впишите
туда `TELEGRAM_BOT_TOKEN`, положите рядом `service_account.json` (например,
через WinSCP) и запустите `sudo bash deploy.sh` ещё раз (повторные запуски
безопасны — ничего не перезатирают). Дальше бот уже работает как
systemd-сервис, отдельно запускать `python -m bot.main` не нужно.

### Вариант В — руками (любая ОС, в том числе Windows)

```bash
python -m venv .venv
source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# отредактируйте .env: TELEGRAM_BOT_TOKEN, GOOGLE_CALENDAR_ID, TIMEZONE и т.д.
# положите service_account.json рядом (или укажите путь в .env)

python -m bot.main
```

После запуска напишите боту в Telegram `/start`, затем `/subscribe` в каждом
чате, куда нужно слать напоминания.

## Команды бота

| Команда        | Действие                                             |
|-----------------|-------------------------------------------------------|
| `/start`        | Приветствие и список команд                          |
| `/help`         | То же самое                                           |
| `/whoami`       | Показать свой chat_id (нужен для `ADMIN_CHAT_IDS`)   |
| `/subscribe`    | Включить напоминания в этом чате                     |
| `/unsubscribe`  | Выключить напоминания в этом чате                     |
| `/today`        | Показать события на ближайшие 24 часа                |
| `/upcoming`     | Показать все события в пределах горизонта просмотра  |
| `/hide_event`   | Скрыть событие только у себя (календарь не трогает, остальных не затрагивает) |
| `/hidden_events`| Вернуть событие, скрытое командой выше               |
| `/status`       | Текущие настройки и статус подписки                  |
| `/olympiads`    | Олимпиады, распознанные в календаре (с датами и ссылками) |

Плюс без каких-либо команд: каждый день в `DAILY_DIGEST_TIME` подписчикам
приходит сводка событий на сегодня.

## Mini App — веб-интерфейс внутри Telegram

По команде `/start` бот показывает кнопку **«📱 Открыть приложение»** —
она открывает полноценное веб-приложение поверх чата (Telegram Mini App):
вкладки «Сегодня», «Календарь», «Олимпиады», «Ещё» (настройки — для
администратора). Делает то же самое, что команды, но в виде обычного
мобильного интерфейса — списки карточками, кнопки, поля ввода вместо
`/set_calendar <id>` и т.п. Админ там же может удалить событие без
набора команд, а любой подписчик — скрыть событие только у себя.
Вкладка «Олимпиады» показывает не справочник сайтов, а сами олимпиадные
события, уже вписанные в календарь (см. «Олимпиады» ниже).

На вкладке «Сегодня» есть блок **«📊 Этот месяц»** — сколько событий
осталось до конца месяца, сколько из них по олимпиадам, и простая
разбивка загруженности по неделям, чтобы сразу понимать, насколько
насыщенный месяц, не открывая отдельно «Календарь».

Если название события, вписанного в календарь вручную, совпадает с одной
из известных олимпиад — на карточке события появляется золотистый акцент
и кнопка **«🏅 Сайт олимпиады»** со ссылкой на первоисточник. Это
определяется по тексту названия (см. `match_source_by_text` в
`bot/olympiads.py`) — то есть не на 100% надёжно (падежные окончания
учитываются, но сильно сокращённое или нестандартное название может не
распознаться).

**Это требует отдельной настройки** — Telegram открывает Mini App только
по HTTPS с настоящим доменом (просто IP недостаточно). Без этой настройки
всё остальное в боте работает как обычно — кнопка просто не появится.
Домен можно завести самому (следующий раздел) либо получить бесплатно
без регистрации через Cloudflare Tunnel (раздел после него).

### Как настроить (бесплатно, через deploy.sh / deploy_from_pc.bat)

1. Получите бесплатный домен, указывающий на IP вашего сервера — проще
   всего через **DuckDNS** (duckdns.org): зарегистрируйтесь, создайте
   поддомен вида `mybot.duckdns.org`, впишите туда IP вашего сервера.
   (Подойдёт и платный свой домен — тоже просто направьте его на IP
   сервера A-записью.)
2. В `.env` впишите:
   ```
   WEBAPP_DOMAIN=mybot.duckdns.org
   ```
3. Запустите `sudo bash deploy.sh` (или `deploy_from_pc.bat` с компьютера)
   ещё раз. Скрипт сам поставит Caddy, который автоматически получит
   HTTPS-сертификат Let's Encrypt для вашего домена и настроит бота на
   кнопку приложения.
4. Подождите пару минут (выпуск сертификата) и напишите боту `/start` —
   должна появиться кнопка «📱 Открыть приложение».

### Mini App без домена (бесплатно, через Cloudflare Tunnel)

Если домен заводить не хочется — есть способ без него, тоже бесплатный:
**Cloudflare Tunnel** в режиме "quick tunnel". Он сам выдаёт случайный
адрес вида `https://случайные-слова.trycloudflare.com` с готовым HTTPS,
без регистрации в Cloudflare.

1. В `.env` впишите:
   ```
   WEBAPP_VIA_CLOUDFLARE_TUNNEL=1
   ```
   (оставьте `WEBAPP_DOMAIN` пустым — если он задан, используется он,
   а не туннель)
2. Запустите `sudo bash deploy.sh` (или `deploy_from_pc.bat`) ещё раз —
   скрипт сам поставит `cloudflared` и настроит всё остальное. Либо
   отдельно: `sudo bash setup_cloudflare_tunnel.sh`.
3. Через 5–15 секунд адрес появится, впишется в `.env` сам, и бот
   перезапустится с кнопкой приложения.

**Важное ограничение** (это особенность самой Cloudflare, не настройки):
такой адрес **меняется при каждом перезапуске туннеля** — например,
после перезагрузки сервера. Отдельная служба `cloudflared-tunnel`
следит за этим и сама обновляет кнопку бота при смене адреса — никаких
действий от вас не требуется, но дайте ей секунд 10–20 после перезапуска
сервера. Если нужен стабильный постоянный адрес — используйте свой домен
(предыдущий раздел), это надёжнее для долгой работы.

Логи туннеля: `journalctl -u cloudflared-tunnel -f`.

### Как это устроено технически

- `webapp/server.py` — отдельный веб-сервер (aiohttp), слушает только
  `127.0.0.1:8787`; наружу (443, HTTPS) смотрит Caddy и проксирует туда.
- `webapp/static/` — сама страница приложения (HTML/CSS/JS), минималистичный
  дизайн на переменных темы Telegram (подстраивается под светлую/тёмную
  тему автоматически).
- Авторизация — через `initData`, который Telegram подписывает и передаёт
  приложению; сервер проверяет подпись по алгоритму Telegram (HMAC-SHA256
  от токена бота), так что получить доступ может только реальный
  пользователь, открывший приложение из Telegram, а не кто угодно по ссылке.
- Это **второй, отдельный процесс** от самого бота (он не умеет принимать
  сообщения в Telegram, только отдаёт веб-страницу и API) — оба процесса
  работают с одной и той же базой `bot_data.sqlite3` и одним календарём.
  Если настройки (интервал опроса, время сводки) меняют через
  приложение — боту может понадобиться до 30 секунд, чтобы это подхватить
  (отдельная фоновая проверка на этот случай, `bot/schedule_sync.py`).

### Запуск вручную (без deploy.sh)

```bash
.venv/bin/python -m webapp.server
```
слушает `127.0.0.1:8787`. Спереди нужен свой реверс-прокси с HTTPS (Caddy,
nginx+certbot и т.п.), проксирующий на этот адрес, и `WEBAPP_URL=https://...`
в `.env`.

## Как поделиться ботом с другими людьми

Бот уже устроен так, что следить за вашим календарём может любой, кому вы
дадите ссылку на бота — им не нужен доступ к самому Google Calendar или к
серверу, где запущен бот.

1. Откройте бота в Telegram (у @BotFather есть кнопка «Открыть бота», либо
   ссылка вида `https://t.me/имя_вашего_бота`) и отправьте эту ссылку тем,
   кому нужны напоминания.
2. Они нажимают Start (или пишут `/start`), затем `/subscribe` — и с этого
   момента получают те же напоминания о том же календаре, что и вы.
3. Отписаться человек может в любой момент командой `/unsubscribe`.

Важно: пока запущен только ваш локальный `python -m bot.main` (или
`run_bot.bat`), бот отвечает только тогда, когда этот процесс работает на
вашем компьютере — поэтому для постоянной доступности имеет смысл настроить
автозапуск (см. «Автозапуск на Windows» ниже) или держать бота на сервере.

Команды `/set_*` при этом остаются доступны только вам — тем чатам, что
перечислены в `ADMIN_CHAT_IDS`, остальные подписчики их использовать не
могут.

## Настройка через Telegram

Часть настроек можно менять прямо в чате с ботом, без правки `.env` и без
перезапуска — изменения применяются сразу же. Доступно только чатам из
`ADMIN_CHAT_IDS`.

**Как включить:**
1. Запустите бота, напишите ему `/whoami` — он ответит вашим `chat_id`.
2. Впишите это число в `.env`:
   ```
   ADMIN_CHAT_IDS=123456789
   ```
   (несколько администраторов — через запятую: `123456789,987654321`)
3. Перезапустите бота — теперь эта команда доступна из указанных чатов.

**Команды администратора:**

| Команда                          | Действие                                    |
|------------------------------------|------------------------------------------------|
| `/config`                          | Показать текущие настройки                  |
| `/set_calendar <id>`                | Сменить календарь (`primary` или email вида `xxx@group.calendar.google.com`) |
| `/set_reminders <60,10>`            | За сколько минут до события напоминать       |
| `/set_olympiad_deadlines <7,1>`     | За сколько дней до закрытия регистрации/отборочного этапа олимпиады напоминать |
| `/set_lookahead <часы>`             | Горизонт просмотра событий                   |
| `/set_interval <секунды>`           | Как часто опрашивать календарь               |
| `/set_timezone <Europe/Moscow>`     | Часовой пояс для отображения времени         |
| `/set_digest_time <ЧЧ:ММ>`          | Время ежедневной сводки событий на сегодня   |
| `/delete_event`                     | Удалить событие из календаря (со списком и подтверждением) |

Эти значения после первого запуска хранятся в базе данных
(`DATABASE_PATH`), а не в `.env` — поэтому дальнейшее редактирование
`.env` для них уже ни на что не влияет, настройки меняются только через
эти команды.

## Удаление события (`/delete_event`)

1. Админ пишет `/delete_event`.
2. Бот присылает список событий на ближайшие 30 дней в виде кнопок.
3. После выбора — просит подтвердить удаление («✅ Да, удалить» / «❌ Отмена»).
4. После подтверждения событие удаляется из Google Calendar **полностью и
   для всех** (не только у вас — оно пропадёт и из календарей всех
   подписчиков бота).

Требует право «Make changes to events» у сервис-аккаунта — см. пункт 2 выше.

### Скрыть у себя — не то же самое, что удалить (`/hide_event`)

Если нужно просто не видеть какое-то событие и не получать по нему
напоминания — **не нужно его удалять** (это затронет всех). Вместо этого
доступна команда `/hide_event` — она есть у любого подписчика, не только
у админа:

1. Пишете `/hide_event`, выбираете событие, подтверждаете.
2. Событие пропадает из `/today`, `/upcoming`, ежедневной сводки и
   напоминаний **только у вас** — сам календарь и остальные подписчики
   это не затрагивает.
3. Вернуть обратно — командой `/hidden_events` (или через Mini App,
   раздел «Ещё» → «Скрытые события»).

## Олимпиады

Бот сам ничего в интернете не читает — список олимпиад с их сайтами
зашит в `bot/olympiads.py` (`SOURCES`), только для распознавания. Все
события по олимпиадам вносятся в календарь вручную (как и любые другие
события) — бот просто **узнаёт по названию события**, что оно про одну
из известных олимпиад (`match_source_by_text` в `bot/olympiads.py`), и
если узнал:

- на карточке события в Mini App и в сетке «Календарь» появляется
  золотистый акцент, бейдж и кнопка со ссылкой на сайт олимпиады;
- кроме обычных напоминаний (`/set_reminders`, считают от начала события)
  включаются отдельные напоминания о приближающемся закрытии регистрации
  или отборочного этапа (`/set_olympiad_deadlines`) — они считают от даты
  **конца** события, что для многодневного окна регистрации гораздо
  полезнее.

Распознавание по названию — это текстовое совпадение, а не надёжная
привязка: может не сработать на сильно сокращённом или нестандартном
названии (падежные окончания при этом учитываются).

Все распознанные олимпиадные события, уже вписанные в календарь (с датами
и ссылкой на сайт) — во вкладке «Олимпиады» в Mini App и командой
`/olympiads`. Если по какой-то олимпиаде в календаре пока нет события —
её там просто не будет, список не статичный
справочник сайтов, а то, что реально ближайшие полгода происходит в
календаре.

## Если бот не отвечает: сервер не может достучаться до Telegram

Встречается у некоторых хостингов/регионов: сервер в принципе не может
подключиться к серверам Telegram (не specифично к этому боту — вообще
никак). Выглядит так: бот запускается, в логах `journalctl -u tgbot -f`
тишина (ни ошибок, ни обработки сообщений), фоновые задачи вроде
`check_reminders` могут при этом исполняться без ошибок (они ходят в
Google Calendar — это другой адрес, он может работать, пока Telegram не
отвечает).

**Проверить напрямую:**
```bash
curl -v --max-time 15 https://api.telegram.org/
```
Если видите `Connection timed out` или `Network is unreachable` — это
подтверждает проблему. Дело не в коде бота — обычный `curl` на сервере
точно так же не достучится.

**Это уже встроено в деплой — отдельно руками делать ничего не нужно.**
И `deploy.sh`, и `deploy_from_pc.bat` (который его вызывает по SSH)
сами проверяют связь с Telegram на шаге «4/5» и, если она не работает,
автоматически поднимают прокси через Cloudflare WARP (см. ниже) и
прописывают его в `.env`. Если после обычного запуска
`deploy_from_pc.bat` (или `sudo bash deploy.sh` на сервере) бот всё
равно не отвечает — смотрите, что скрипт написал на этом шаге:

1. «Telegram доступен напрямую» — проблема не в блокировке, ищите
   причину в другом (токен, логи `journalctl -u tgbot -f`).
2. «Cloudflare WARP помог» — всё настроено автоматически, прокси уже
   прописан, бот перезапущен.
3. «Cloudflare WARP не помог» — значит, провайдер блокирует и само
   подключение WARP (оно идёт по UDP на порт 2408, его тоже иногда
   режут DPI). Нужен **zapret** — см. следующий раздел.

Также можно написать в поддержку хостинга (спросить про блокировку
IP-диапазонов Telegram, `149.154.160.0/20` и похожих) или перенести
бота на сервер в другом регионе/у другого провайдера — но WARP чаще
всего решает проблему без этого.

### Как это работает (`setup_warp_proxy.sh`)

Такая блокировка (сервер не видит именно IP-диапазоны Telegram) типична
для некоторых российских хостингов/провайдеров — это блокировка на уровне
DPI у оператора, а не проблема бота. Один из рабочих способов —
[Cloudflare WARP](https://developers.cloudflare.com/warp-client/): его
официальный клиент можно поднять в режиме локального SOCKS5-прокси, и
весь трафик бота к Telegram пойдёт через сеть Cloudflare, а не прямо к
IP Telegram. Именно это и делает `setup_warp_proxy.sh`, автоматически
вызываемый из `deploy.sh`:

1. Поставит `cloudflare-warp` из официального репозитория Cloudflare;
2. Зарегистрирует клиента и включит режим `proxy` (локальный
   SOCKS5 на `127.0.0.1:40000`);
3. Проверит, отвечает ли Telegram через этот прокси;
4. Если да — впишет `TELEGRAM_PROXY_URL=socks5h://127.0.0.1:40000` в `.env`
   и перезапустит `tgbot.service`. Если нет — ничего в `.env` не трогает
   (чтобы не прописать нерабочий прокси) и говорит, что нужен zapret.

Если нужно прогнать его отдельно (например, после того как поставили
zapret) — запустите на сервере, от root:
```bash
cd ~/tgbot
sudo bash setup_warp_proxy.sh
```

> Команды `warp-cli` слегка отличаются между версиями клиента — скрипт
> пробует несколько вариантов, но если у вас другая версия и что-то не
> сработало, выполните `warp-cli --help` на сервере и пришлите вывод —
> команды в скрипте легко поправить под конкретную версию.

### Если блокируют и WARP: zapret

[zapret](https://github.com/bol-van/zapret) — отдельная утилита для обхода
DPI-блокировок на уровне пакетов (фрагментация TLS/QUIC, подмена TTL и
похожие приёмы). В отличие от WARP (прокси только для одного процесса —
бота), zapret работает на уровне iptables/nftables всего сервера и обычно
требует подбора стратегии именно под блокировку конкретного провайдера —
готового универсального рецепта нет, разработчики поэтому и поставляют
инструмент для автоматического подбора:

```bash
git clone https://github.com/bol-van/zapret.git
cd zapret
# Подбирает рабочую стратегию обхода для конкретного хоста.
# Если боремся за подключение WARP — проверяем его хост и порт:
sudo ./blockcheck.sh engage.cloudflareclient.com:2408

# Если боремся напрямую за Telegram (без WARP вообще):
sudo ./blockcheck.sh api.telegram.org:443
```

`blockcheck.sh` переберёт несколько стратегий обхода и покажет, какая
сработала. После этого разворачиваете найденную стратегию постоянно:
```bash
sudo ./install_easy.sh
```
(спросит, какую стратегию закрепить — берите ту, что показал
`blockcheck.sh`). Дальше либо просто повторно запустите
`setup_warp_proxy.sh` (если целились в WARP), либо, если целились прямо
в Telegram, уберите `TELEGRAM_PROXY_URL` из `.env` — трафик до Telegram
теперь должен проходить напрямую благодаря zapret, без прокси вообще.

> Это системная настройка с подбором параметров под конкретную сеть —
> нет гарантии, что сработает с первой попытки, и нельзя настроить
> «заранее» без доступа к реальному серверу. Если `blockcheck.sh` не
> находит рабочую стратегию — пришлите его вывод, попробуем разобраться
> по конкретной ошибке.

## Автозапуск на Windows

Чтобы бот сам запускался при включении компьютера (или входе в систему),
используйте готовый файл `run_bot.bat` — он сам перезапускает бота, если
тот упадёт (например, из-за обрыва сети).

### Способ 1 — папка автозагрузки (самый простой)

1. Нажмите `Win + R`, введите `shell:startup`, нажмите Enter — откроется
   папка автозагрузки.
2. Кликните правой кнопкой по файлу `run_bot.bat` в папке проекта →
   «Создать ярлык» (или «Отправить» → «Рабочий стол», а потом перетащите
   ярлык в открывшуюся папку автозагрузки).
3. Готово — при следующем входе в Windows откроется чёрное окно, в котором
   будет работать бот. Не закрывайте это окно, пока хотите получать
   напоминания.

Минус способа: бот запустится, только когда вы войдёте в свою учётную
запись Windows (не сразу при включении компьютера, если у вас есть экран
входа с паролем).

### Способ 2 — Планировщик заданий (надёжнее)

1. Нажмите `Win + R`, введите `taskschd.msc`, нажмите Enter.
2. Справа нажмите **«Создать простую задачу»**.
3. Имя: например, «Telegram Calendar Bot» → Далее.
4. Триггер: **«При входе в систему»** → Далее.
5. Действие: **«Запустить программу»** → Далее.
6. В поле «Программа или сценарий» нажмите «Обзор» и выберите файл
   `run_bot.bat` в папке проекта → Далее → Готово.

Чтобы бот перезапускался при сбоях автоматически (без открытого окна):
откройте созданную задачу → «Свойства» → вкладка **«Параметры»** →
поставьте галочку «Перезапускать через» и укажите интервал (например,
1 минута) и число попыток.

## Запуск как systemd-сервиса на Linux/сервере (пример)

Если разворачивали через `deploy_from_pc.bat` или `deploy.sh` (варианты А/Б
выше) — этот юнит уже создан и запущен автоматически, этот раздел можно не
делать. Пригодится, если настраивали руками (вариант В).

```ini
[Unit]
Description=Telegram Google Calendar reminder bot
After=network.target

[Service]
WorkingDirectory=/opt/tgbot
ExecStart=/opt/tgbot/.venv/bin/python -m bot.main
EnvironmentFile=/opt/tgbot/.env
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

## Запуск через Docker (альтернатива venv + systemd)

Не нужно вручную ставить Python/venv на сервере — достаточно Docker.

**1. Установить Docker на сервере** (Ubuntu/Debian):

```bash
curl -fsSL https://get.docker.com | sh
```

**2. Подготовить файлы рядом с `docker-compose.yml`:**
- `.env` — со всеми переменными (см. `.env.example`); добавьте/поправьте строку
  ```
  DATABASE_PATH=/app/data/bot_data.sqlite3
  ```
  (это путь внутри контейнера — данные сохранятся в папке `./data` на сервере
  и переживут пересборку/перезапуск контейнера)
- `service_account.json` — ключ сервис-аккаунта Google

**3. Собрать и запустить:**

```bash
docker compose up -d --build
```

**Полезные команды:**

```bash
docker compose logs -f      # смотреть логи бота в реальном времени
docker compose restart      # перезапустить
docker compose down         # остановить и удалить контейнер (данные в ./data останутся)
docker compose up -d --build   # пересобрать и перезапустить после обновления кода
```

Автозапуск при перезагрузке сервера уже встроен (`restart: unless-stopped` в
`docker-compose.yml`) — отдельный systemd-юнит для этого не нужен.

## Сколько места занимает бот

Измерено напрямую (venv-вариант, Linux):

| Компонент | Размер |
|---|---|
| Сам код бота | 252 КБ |
| venv со всеми зависимостями | ~150 МБ |
| — из них `google-api-python-client` | 109 МБ (тащит discovery-документы вообще всех Google API, не только Calendar) |
| — из них `aiohttp` (веб-сервер Mini App) | ~15 МБ |
| База данных SQLite | сотни КБ — несколько МБ (старые записи чистятся автоматически) |
| Caddy (для HTTPS Mini App, если задан `WEBAPP_DOMAIN`) | 38 МБ (измерено — настоящий пакет, не snap) |

**Итого:** около **150 МБ** (без Mini App) или **~190 МБ** (с Mini App,
то есть с Caddy). В любом случае это укладывается в диск самого дешёвого
VPS-тарифа (обычно 15–25 ГБ) с огромным запасом.
